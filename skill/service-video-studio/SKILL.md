# 서비스 소개 영상 제작

실제로 돌아가는 제품 화면이 주인공인 한국어 내레이션 영상을 만든다. 기준작은 Omni AI Trading 소개 영상(3분 33초, https://youtu.be/c4FZw6AYRAg)이다. 그 영상은 두 번 갈아엎고 나서야 확정됐다. 이 스킬은 처음부터 확정판의 순서로 간다.

## 품질 기준 (이것이 '같은 퀄리티')

1. **실제 제품이 움직인다.** 화면 파트마다 실제 녹화가 2~8초 있고, 정지 화면만으로 채운 파트가 없다. 반대로 **녹화를 그대로 틀어 놓기만 한 파트도 없다**: 1:1 화면은 글자가 작고 빈 곳이 많아 금방 지루하다. 누르는 순간은 녹화로, 짚어 말하는 순간은 SpotTour로, 숫자·구조는 모션으로 바꾼다.
2. **말과 화면이 같은 순간을 가리킨다.** 강조는 그 단어보다 0.15~0.2초 먼저 시작하고, 어느 칸인지 테두리와 이름표로 바로 읽힌다. 결과 숫자는 화면 구석의 카드로 두지 않고 크게 다시 그린다.
3. **지루한 공백도, 쫓기는 느낌도 없다.** 문장 사이 1초, 파트 사이 1.5초, 음성 1.1배속(음높이 유지).
4. **한 사람이 만든 것처럼 보인다.** 바탕 하나, 강조색 하나(장면마다 한 곳), 글꼴은 Pretendard, 글자 등장은 한 가지 방식.
5. **모든 주장에 근거가 있고, 가려야 할 값은 한 프레임도 나오지 않는다.**
6. 재료가 섞여 있다: 2분 이상이면 Remotion 샷 3개·모션 파트 3개 이상, 1분이면 샷 1~2개·숫자나 도식 모션 1~2개, 30초여도 샷 1개와 숫자 모션 1개. 같은 샷을 이어 쓰지 않는다.
7. 1920×1080 30fps, −14 LUFS(±1), 최고 0 dBTP 미만, 길이는 시간표와 0.3초 안.

## 준비

- 필요한 것: Python 3.12+, Node, ffmpeg, ego-browser(녹화), 음성은 로컬 모델(`install.py --local-tts`) 또는 `FISH_AUDIO_API_KEY`. 받아쓰기는 HyperFrames가 스스로 한다(첫 실행에 모델을 받음). `npx hyperframes@0.9.72`·Remotion 4.0.484로 확인했다.
- `S=<이 스킬>/scripts`, `W=<작업 폴더>`. 작업 폴더는 프로젝트의 git 제외 경로에 둔다(녹화·렌더가 수백 MB다). 저장소 안이면 `.gitignore`부터 확인한다.
- 도구 점검: `python3 $S/selftest.py`
- 사용자가 이미 준 파일·대본·영상이 있으면 그 단계부터 시작한다. 파일로 어디까지 됐는지 판단하고, 된 것을 다시 만들지 않는다.

## FLOW

```
S1 기획 → [승인 1] → S2 대본·검수 → S3 음성·시간표·자막 → S4 스토리보드 → [승인 2]
→ S5 녹화·가림 → S6 장면 제작(파일럿 2파트 → [승인 3] → 나머지) → S7 합성·소리 → S8 검수 → [승인 4] → S9 게시
```

| 단계 | 반드시 남길 파일 |
| --- | --- |
| S1 | `PLAN.md` (메시지 · 파트 표 · **가림 목록** · 정한 것과 이유) |
| S2 | `script.json`, `SCRIPT.md`, `RECIPES.md`(고른 레시피·배경음·효과음과 이유) |
| S4 | `SPEC.md`, `boards/storyboard.html` |
| S5·S6 | `capture/*.scene.js`, `compositions/*.html`, `remotion/tours.json` |
| S8 | `qa/`, `REPORT.md` (품질 기준 1~7마다 근거 한 줄, 못 한 것) |

승인 지점에서는 결과물을 보여 주고 멈춘다. 파트 하나를 다 만든 뒤 방향이 틀린 것을 알면 비용이 몇 배라서다. 사용자가 "끝까지 알아서"라고 했으면 승인 1~3은 스스로 정하고 `PLAN.md`에 이유를 적되(파일과 스토리보드는 그대로 만든다), **S9 공개 게시는 언제나 따로 승인받는다**(되돌리기 어렵다). 물어볼 것은 권장안을 먼저 적어 한 번에 묻는다.

`script.json` 하나가 원본이다. 대본·읽기·파트·쉼·자막 밝기·효과음이 모두 여기 있고, 시간표·자막·`index.html`은 여기서 다시 만들어진다. 생성된 파일을 손으로 고치지 않는다.

### S1 기획 → `PLAN.md`

1. 제품을 직접 조사한다: README, 문서, **브라우저로 연 실제 화면**(소스만 읽지 않는다). 영상이 전할 한 문장과 기억시킬 세 가지를 정한다.
2. 파트 표(훅 → 왜 → 한눈에 → 핵심 기능 2~4 → 복기·증거 → 마무리): 길이, 보여 줄 화면, 촬영 방법.
3. **가림 목록**을 여기서 정한다: 무엇을 왜 가리는지, 무엇은 보여도 되는지. 금액뿐 아니라 수익률·승률·건수·시각·계좌 이름·사람 이름·이메일·경로까지 본다. → `references/capture.md`
4. 길이(권장 1~3분 30초), 목소리, 배경음, 게시할 곳, 강조색을 묻는다. "지난번처럼"이면 아래 기준작 값을 권장안으로 적는다. 제출처의 길이 제한이 있으면 먼저 확인한다.

| 길이 | 문장 | 파트(초) |
| --- | --- | --- |
| 30초 | 6~7 | 훅 6 · 핵심 기능 14 · 결과 숫자 6 · 마무리 4 |
| 1분 | 11~13 | 훅 8 · 한눈에 10 · 기능 둘 12+13 · 결과 10 · 마무리 7 |
| 3분 30초 | 28~30 | 훅 15 · 왜 21 · 한눈에 25 · 화면 파트 넷 25씩 · 운영 13 · 마무리 11 |

**기준작 값**: 목소리 Fish API `ca3becd0…`(차분한 중년 남성. 로컬이면 이 컴퓨터에 저장한 기본 목소리를 참조하고, 저장한 것이 없으면 기본 설계), 1.1배속, 쉼 1초/1.5초, 바탕 #131209 · 글자 #f3f4f5 · 강조 #ff6600(다른 제품이면 그 제품 색), Pretendard, 배경음 Mixkit 'Tonight'(처음 쓸 때 자동으로 받음), 노래방식 자막.

### S2 대본 → `script.json`, `SCRIPT.md`

`python3 $S/new_project.py $W "<제목>" 25-40`(목표 초)로 폴더를 만들고 `script.json`의 `parts`·`lines`를 채운다. 문장마다 `cap`(자막), `kind`(말하는 내용의 종류), `screen`(보이는 것), `fact`(근거). 한 문장은 한 장면에서 한 가지만 말한다.

`python3 $S/review_script.py $W` 가 문제 없음이 될 때까지 고친다. 그다음 사실 대조(문장마다 근거를 실제로 열어 본다)와 korean-polish 스킬 기준의 문장 검토를 하고 사용자에게 대본을 보여 준다. 음성을 만든 뒤 대본을 고치면 장면까지 다시 맞춰야 한다. → `references/script-voice.md`

**레시피와 소리는 자동으로 고른다.** 제품의 분위기를 `mood`(`calm` 차분·`heavy` 묵직·`bright` 경쾌·`fast` 빠름)로 정하고 `python3 $S/pick.py $W`를 돌리면 문장의 `kind`에 어울리는 레시피, 배경음, 효과음 세트를 골라 `RECIPES.md`에 이유와 함께 적는다. 묻지 않고 이 선택으로 진행하되, 승인 지점마다 `RECIPES.md`를 함께 보여 주고 "바꾸고 싶은 장면·음악을 말하면 그것만 바꾼다"고 알린다. 고르는 법과 바꾸는 법은 아래 '레시피와 소리'.

### S3 음성·시간표·자막

```bash
python3 $S/tts.py $W                    # 문장별 음성(바뀐 문장만). 엔진은 script.json voice_engine
python3 $S/timeline.py $W               # 1.1배속 + 쉼 → timeline.json. 길이를 여기서 확정
python3 $S/words.py $W                  # 단어 시각 + 자막. 출력의 +초(장면 시작 기준)를 S6에서 그대로 쓴다
python3 $S/make_index.py $W             # index.html, 장면 틀
```

음성 엔진은 셋이다. 로컬 모델이 설치돼 있으면 새 프로젝트의 기본은 `drama-3`다.

| `voice_engine` | 어디서 | 쓸 수 있는 곳 | 고를 때 |
| --- | --- | --- | --- |
| `drama-3` | 이 컴퓨터(글이 밖으로 나가지 않음) | 상업 이용 가능(12개월 매출 50만 달러 미만) | 기본. 목소리 설계·말투·목표 길이·대사 안 지시를 모두 씀 |
| `s2-pro` | 이 컴퓨터 | **연구·비상업만** | 비상업 영상에서 두 번째 후보로 견줄 때 |
| `fish-api` | Fish Audio 무료 API | API 약관 | 로컬 모델이 없을 때, 기준작과 같은 목소리(`ca3becd0…`)가 필요할 때 |

옵션은 `python3 $S/tts.py --options`, 쓰는 법은 `references/script-voice.md` '로컬 음성'. "목소리를 바꿔줘"면 `--audition 4`로 후보를 만들어 들려주고 고르게 한다.

**장면보다 시간표가 먼저다.** 다 만든 영상을 나중에 자르고 배속하면 전환과 효과음이 잘린다. 시간표가 목표 길이를 벗어나면 문장을 줄이고 S2로 돌아간다. 길이가 맞으면 음성을 한 번 들어 보고(발음·끊김) 넘어간다. `words.py`가 받아 적은 말이 대본과 다르다고 하면 그 문장의 `opts.seed`를 바꿔 다시 만든다.

### S4 스토리보드 → `boards/storyboard.html`

문장마다 정지 스케치 한 장(핵심 화면), 시각, 내레이션, 움직임, 쓸 방식(녹화 / SpotTour / HyperFrames 모션). 장면 종류가 세 번 이어서 같지 않게 섞는다. `SPEC.md`(목표 한 문장·색·글꼴·움직임·금지)를 이 제품에 맞게 채운다. 사용자가 "녹화 영상이 없다"고 나중에 놀라지 않도록, **어느 장면이 실제 녹화이고 어느 장면이 정지 화면+카메라인지 표에 분명히 적는다.**

### S5 녹화·가림 → `assets/clips/*.mp4`, `assets/img/*.jpg`

가림 규칙을 `capture/mask.config.json`에, 파트의 움직임을 `capture/<이름>.scene.js`에 쓰고(예: `example.scene.js`) 한 번에 찍는다. 조회만 하고 저장·전송·결제·주문·삭제는 누르지 않는다.

```bash
python3 $S/record.py $W p2 http://127.0.0.1:포트/   # → assets/clips/p2.mp4 + 표시 시각 + 칸 좌표(SpotTour용) + still 정지 화면
```

화면이 헐렁하면 `css`를 1280~1440으로 줄여 같은 1920×1080에 글자를 크게 담는다. **찍을 때마다 표·팝업·도식 프레임을 원본 크기로 확대해 가림을 확인한다**(축소 시트에서는 누락이 안 보였다). → `references/capture.md`

### S6 장면 제작 → `compositions/pN.html`

파일럿으로 성격이 다른 두 파트(도식 하나, 실제 화면 하나)를 먼저 끝까지 만들어 보여 준다. 세 가지 재료를 섞는다.

| 재료 | 언제 |
| --- | --- |
| **실제 녹화** | 누르면 열린다·목록을 훑는다처럼 '진짜 돌아간다'를 보일 때 |
| **Remotion 샷 7개**(shotcraft 방식, 값만 넣음) | SpotTour 여러 칸 짚기 · TextMask 글자 오프닝 · CrashZoom 한 칸 강조 · TiltGlide 전체 훑기 · BeforeAfter 앞뒤 비교 · CardFlip 화면 전환 · Lockup 마무리. `remotion/tours.json`에 `shot`과 값 |
| **다른 shotcraft 샷** | 사용자가 이름으로 고르거나 위 것으로 안 될 때 `add_shot.py`로 가져와 고친다 |
| **HyperFrames 모션** | 구조·흐름·숫자·조건처럼 화면에 없는 것을 설명할 때. 장면 틀의 `rev·count·draw·cam·slam` |

완성 장면 예가 `assets/examples/`에 있다(p1 통계 카드, p2 구조·흐름, p4 녹화+입력 모음+SpotTour+기록 카드, p5 단계·스위치·한도, p9 마무리). 새 장면을 쓰기 전에 성격이 비슷한 것을 하나 읽는다. 안의 이미지·영상 경로와 문구는 기준작 것이라 바꿔 쓴다.

→ `references/motion.md` (SpotTour 좌표 재는 법, HyperFrames 함정, 장면별 처방)

### S7 합성·소리

```bash
cd $W && npx --yes hyperframes@0.9.72 check          # 오류 0
npx --yes hyperframes@0.9.72 snapshot --at 3,8.5,14   # 장면마다 눈으로 본 뒤
npx --yes hyperframes@0.9.72 render --output renders/vo.mp4
python3 $S/mix_audio.py $W renders/vo.mp4 renders/final.mp4
```

고친 파트만 빠르게 볼 때는 `render --start A --end B`. 효과음은 `script.json`의 `sfx`에 장면 안 시각으로 적는다(장면당 1~2종류, 화면 움직임과 같은 순간).

### S8 검수

`python3 $S/qa.py $W renders/final.mp4` → 파트마다 쓴 재료 수를 품질 기준 1·6과 견주고, `확인:`으로 나온 빈 화면·정지 구간을 고치거나 이유를 적는다. 기계 검사 통과 뒤 다음을 **직접** 한다.

1. `qa/frames/*.jpg`를 원본 크기로 보며 가림 목록을 하나씩 대조한다. 공개하면 되돌릴 수 없으니 의심스러우면 다시 찍는다.
2. 화면 글자 ↔ 내레이션 ↔ 이름표가 같은 말을 하는지 본다. 다르면 실제 화면 글자 쪽으로 맞춘다.
3. `qa/sync`의 강조 단어가 출력과 같은지 본다.
4. `watch` 스킬에 최종본 경로와 `--engine local`을 주어 처음부터 끝까지 본다(Gemini 엔진은 원본을 밖으로 올리니 쓰지 않는다). 건너뛰지 않는다. 듣지 못했으면 못 들었다고 보고한다.

보고에는 확인한 것과 확인하지 못한 것을 나눠 적고, 화면에 남아 있는 민감할 수 있는 값은 작아 보여도 모두 알린다. 확정되면 `output/`에 최종본과 공유용(1280px)을 두고, `PLAN.md`에 제작 이력(판·바뀐 점·다시 만드는 순서)을 남긴다.

## 레시피와 소리 (자동 선택과 사용자 지정)

| 하고 싶은 것 | 명령 |
| --- | --- |
| 자동으로 고르기(여러 번 돌려도 됨) | `python3 $S/pick.py $W` |
| 사용자가 고른 것으로 고정 | `python3 $S/pick.py $W --set S04=CrashZoom P9=Lockup --bgm house-vibez --kit soft --mood bright` |
| 지정을 풀고 다시 자동 | `python3 $S/pick.py $W --auto S04 bgm kit` |
| 고를 수 있는 것 | `python3 $S/pick.py $W --list [낱말]` (shotcraft 124개 포함, 사용자에게는 한국어로 옮겨 보여 준다) |
| 배경음 들어 보기 | `python3 $S/mix_audio.py $W --preview` → `previews/*.mp3`(내레이션에 후보 곡을 깐 20초) |
| shotcraft 원본 샷 가져오기 | `python3 $S/add_shot.py $W <이름>` |

- `by: "user"`인 것은 자동 선택이 바꾸지 않는다. 사용자의 말("오프닝을 글자 나오는 걸로", "음악 좀 더 밝게", "음악 빼줘", "이 파일로 깔아줘")을 위 명령으로 옮기고, **요청한 것만** 바꾼다. 음악을 밝게는 `--bgm`(곡 지정)으로, 영상 전체 분위기를 바꾸라는 말일 때만 `--mood`.
- 요청이 막연하면 후보 2~3개를 한국어로 설명하고(음악은 미리듣기 파일을 보낸다) 고르게 한다. 하나로 정해지면 묻지 않고 반영한다.
- 바꾼 뒤에 다시 하는 일: **배경음·효과음만** → `mix_audio.py`만. **레시피** → 그 문장의 장면(샷 렌더 → compositions → check → 그 파트 렌더 확인) → 전체 렌더 → mix. 대본·음성·시간표는 그대로다. 바뀐 것과 안 바뀐 것을 보고한다.
- 자동 선택이 장면에 맞지 않으면(칸이 하나뿐인데 SpotTour, 앞뒤 화면이 없는데 BeforeAfter) `kind`를 고쳐 다시 돌린다. `by: "user"`는 사용자가 실제로 말한 것에만 쓴다.
- 곡은 장르·빠르기와 잰 크기로 고른다. 에이전트는 곡을 듣지 못하므로 "어울린다"고 단정하지 말고 이유와 미리듣기를 준다. 4곡과 파일 효과음은 처음 쓸 때 Mixkit에서 받는다(웹·소셜 영상에 무료, **TV·라디오·게임·CD에는 음악을 쓸 수 없다**, `assets/NOTICE.md`). 사용자가 준 곡은 공개 영상에 써도 되는지 한 번 확인한다.
